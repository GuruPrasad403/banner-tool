Quick start · Windows

Banner Validator &
Screenshot Tool

Clone or download the project, install its runtime requirements, and run your first banner check.

Repository: github.com/GuruPrasad403/banner-tool

This local tool checks HTML banner dimensions and key sections, then captures the banner while scrolling through its Important Safety Information (ISI) content.

1. What you need

RequirementDetails
Operating systemWindows 10 or later recommended.
Node.jsVersion 18 or later; use a current LTS release (Node.js 20 or 22 recommended). npm is included with Node.js.
Git (optional)Needed only if using the clone command. Alternatively, download the repository as a ZIP from GitHub.
BrowserCurrent Chrome or Microsoft Edge to use the dashboard.
InternetNeeded to clone/download the project and install npm packages. Puppeteer may download its browser on the first install.
Local portsPorts 3000 and 3001 must be available while the app is running.

After installing Node.js, open PowerShell or Command Prompt and confirm:

node --version
npm --version

The Node version should be v18 or higher. If Windows cannot find node or npm, reopen the terminal after installing Node.js.

2. Get the project

Option A — Clone with Git

Open PowerShell or Command Prompt in the folder where you want the project, then run:

git clone https://github.com/GuruPrasad403/banner-tool.git
cd banner-tool

Option B — Download from GitHub

  1. Open the repository link above.
  2. Select Code → Download ZIP.
  3. Extract the ZIP file, then open a terminal in the extracted banner-tool folder.

Tip: In File Explorer, open the project folder, click the address bar, type powershell, and press Enter to open a terminal in that folder.

3. Install and start the application

  1. From the project folder, install the project packages:
npm install
  1. Start the UI and its local backend together:
npm run dev
  1. Wait for the startup messages, then open http://localhost:3000 in Chrome or Edge.

Keep the terminal open while testing. To stop the app, return to the terminal and press Ctrl+C.

4. Run a banner check

A. Choose the input file

In Upload or Select Banner Input, either upload one .html/.htm file or upload a .zip package containing the HTML and its local CSS, JavaScript, images, and other assets. Keep the asset folder structure intact inside the ZIP.

For a quick check without preparing a banner, use Local Path / Fixtures and select one of the built-in sample buttons.

B. Select a size profile

ProfileExpected size
Mobile Small300 × 250 px
Mobile Large320 × 480 px
Leaderboard728 × 90 px
Half Page300 × 600 px
Custom DimensionsEnter the required width and height manually.

Confirm Expected Width and Expected Height match the banner specification. These are CSS pixels.

C. Check or update the section selectors

UI fieldWhat to enterExample
Root Banner SelectorHTML ID or class for the complete banner frame.#banner
Fixed Section SelectorsHeader/body IDs or classes, comma-separated.#header, #body-copy
Nested Scrollable ISI SelectorID or class for the scrollable ISI area.#isi-container

These example selectors are prefilled defaults. If the supplied HTML uses different IDs/classes, change the values to match it. Standard CSS selector notation applies: prefix an ID with # and a class with ..

Banner ID: There is no separate Banner ID input in the current UI. The uploaded file name identifies the job in the tool; it is not necessary to invent or enter a banner ID.

D. Image and scroll options

  • Device Scale Factor: 2x is the default and gives sharper screenshots; 1x or 3x can be chosen if needed.
  • Scroll Overlap: The number of pixels repeated between adjacent ISI screenshots. The profile default is usually fine.

E. Validate and capture

  1. Click Initialize Job & Selectors to load the banner and inspect its sections.
  2. Review the detected banner, header/body, and ISI areas and the validation report.
  3. Click Validate & Capture Screenshots to validate and automatically capture the banner while scrolling the ISI area.
  4. Review the generated screenshot gallery and validation report in the dashboard.

Output files are created locally in the project’s output folder. Temporary processing files are placed in temp. These generated folders are excluded from Git.

5. Common setup issues

IssueWhat to try
node or npm is not recognizedInstall Node.js 18+, close and reopen the terminal, and check the version commands again.
npm install fails or stallsConfirm internet access, then rerun npm install. The initial install may take time to fetch dependencies and Puppeteer’s browser.
Port 3000 or 3001 is already in useClose the other application using that port, then stop and restart this tool with npm run dev.
Sections are not detectedCheck that the selector values exactly match the IDs/classes in the HTML. Include # for an ID or . for a class.
Images or styles are missingUpload a ZIP containing the HTML and its related local assets, preserving their folder paths.
